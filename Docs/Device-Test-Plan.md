# تست روی دستگاه فیزیکی اندروید — Arena

این سند مسیر نصب و سناریوهای تست دستی نسخهٔ اندروید را تعیین می‌کند. هدف، بستنِ
تنها شکاف تأییدنشدهٔ «قابل بازی بودن» است: تا وقتی APK روی گوشی واقعی اجرا نشود،
رندر، FPS، لمس همزمان و شبکهٔ hotspot فقط در Play Mode تأیید شده‌اند، نه روی سخت‌افزار.

## ۱. پیش‌نیازها

- **نسخهٔ اندروید:** حداقل **Android 8.0 (API 26)** — `minSdkVersion` پروژه `AndroidApiLevel26` است. حداقل یک دستگاه **arm64** لازم است (APK فقط `arm64-v8a` دارد).
- **Developer Mode:**
  1. در گوشی به `Settings → About phone` بروید.
  2. هفت بار روی `Build number` ضربه بزنید تا پیام «You are now a developer» بیاید.
  3. برگردید به `Settings → System → Developer options` و آن را روشن کنید.
- **USB Debugging:** در `Developer options` گزینهٔ `USB debugging` را روشن کنید.
- **کابل/درایور:** کابل USB داده‌دار وصل کنید و اجازهٔ «Allow USB debugging» را روی گوشی بپذیرید (کلید `Always allow from this computer` را بزنید).
- **ابزار روی کامپیوتر:** `adb` (از Android platform-tools). اگر Unity Android SDK نصب دارد، معمولاً در
  `<AndroidSdk>/platform-tools/adb` است. بررسی کنید:
  ```bash
  adb version
  adb devices
  ```
  باید شناسهٔ دستگاه با وضعیت `device` دیده شود (نه `unauthorized` یا `offline`).

## ۲. مسیر نصب

فایل APK در `build/outputs/Arena.apk` ساخته می‌شود (Development Build خاموش).

```bash
# نصب / جای‌گذاری نسخهٔ قبلی
adb install -r build/outputs/Arena.apk

# اجرای بازی
adb shell am start -n com.faramacci.arena/com.unity3d.player.UnityPlayerActivity

# اگر نصب با خطای INSTALL_FAILED_UPDATE_INCOMPATIBLE خورد (تغییر امضا/پکیج)، اول حذف کنید:
# adb uninstall com.faramacci.arena
```

> بستهٔ اپ: `com.faramacci.arena` (از نسخهٔ قالب URP به این مقدار تغییر کرده است).

## ۳. سناریوهای تست دستی

### ۳.۱ اجرای بازی و منوی اصلی
- اپ را از لیست برنامه‌ها باز کنید.
- **انتظار:** بازی در حالت **landscape** باز می‌شود (حتی اگر چرخش خودکار گوشی خاموش باشد)، بدون splash طولانی یا کرش. منوی اصلی با دکمه‌های انتخاب حالت (Solo / Host / Join)، انتخاب شخصیت و شکل زون دیده می‌شود.
- بازی را در حالت پرتره نگه دارید: نباید بچرخد.

### ۳.۲ حرکت با لمس و مهارت‌ها (دو انگشتی همزمان)
- `Solo` را بزنید و یک مسابقه با بات شروع کنید.
- با **انگشت چپ** جوی‌استیک را بچرخانید و همزمان با **انگشت راست** یک مهارت را بزنید.
- **انتظار:** هر دو ورودی همزمان کار کنند؛ جوی‌استیک سمت مخالف انگشت را نگیرد؛ هر سه مهارت شلیک شوند و نوار cooldown پر شود؛ پس از ضربه، سلامت نام‌پلیت پایین برود.
- حداقل یک‌بار هر سه شخصیت (Vanguard، Mage و Assassin) و هر دو شکل زون (Circle/Square) را امتحان کنید.

### ۳.۳ شبکهٔ hotspot بین دو دستگاه (اگر دستگاه دوم موجود بود)
- روی گوشی اول Hotspot را روشن کنید و گوشی دوم را به همان Wi-Fi وصل کنید (VPN خاموش).
- گوشی اول: تایل `LOCAL AREA NETWORK` → نقش `HOST` → انتخاب شخصیت و شکل زون → `HOST BATTLE` → آدرس‌های IPv4 در خط وضعیت نشان داده می‌شوند.
- گوشی دوم: همان تایل → نقش `JOIN` → کشف خودکار میزبان آدرس را داخل کادر می‌نویسد (پیام `Found host …`) → `JOIN BATTLE`. وارد کردن دستی آدرس فقط زمانی لازم است که پیام `Searching the hotspot for a host…` بماند.
- **انتظار:** مسابقه خودکار وارد شمارش معکوس می‌شود؛ حرکت هر گوشی مستقل است؛ هر دو گوشی سلامت یکسان می‌بینند؛ یک گوشی win/KO و دیگری برعکس را می‌بیند؛ خروج یک بازیکن، طرف دیگر را به منو برگرداند.
- **انتظار برای حالت انتظار/خطا:** دکمهٔ اصلی در حالت انتظار `CANCEL` است و انتظار را می‌بندد؛ اگر اتصال شکست بخورد همان صفحهٔ انتخاب مبارز می‌ماند، خطای قرمز زیر گزینه‌ها می‌آید و دکمه برای تلاش دوباره فعال است (بازگشت به منو نباید اتفاق بیفتد).
- **۱۰ مسابقهٔ متوالی** بگیرید تا قابلیت اتصال مجدد و آزاد شدن پورت (TCP `28741`) سنجیده شود.
- جزئیات بیشتر: [HotspotMultiplayer.md](HotspotMultiplayer.md).

### ۳.۴ پایداری و FPS
- **۵ دقیقه بازی مداوم** (در Solo با بات کافی است) روی هر دستگاه.
- **انتظار:** بدون کرش، بدون افت فریم محسوس، بدون گرمای غیرعادی، بدون نشت افکت (اورب/رینگ قدیمی روی صفحه نماند). هدف ۶۰ FPS است (`Application.targetFrameRate = 60`).
- لاگ زنده را همزمان ببینید:
  ```bash
  adb logcat -s Unity
  ```
  یا از منوی Unity: **Tools > Arena > Build and Test on Device** (که لاگ را در `build/outputs/logcat-unity.txt` ذخیره می‌کند).

## ۴. معیارهای قبولی (Acceptance Criteria)

تست روی دستگاه **پاس** است اگر همهٔ موارد زیر برقرار باشند:

1. APK بدون خطا روی دستگاه `arm64` نصب و اجرا می‌شود و در landscape باز می‌شود.
2. منوی اصلی کامل رندر می‌شود (بدون UI سیاه/ناقص) و هر دو شخصیت و هر دو زون انتخاب‌پذیرند.
3. حرکت + شلیک **دو انگشتی همزمان** بدون تداخل کار می‌کند.
4. مهارت‌ها: هر سه اسلات شلیک، cooldown، آسیب، stun/knockback و KO/WIN/DRAW درست کار می‌کنند.
5. (اگر دو دستگاه بود) یک مسابقهٔ کامل Host/Join روی hotspot بدون قطعی ناخواسته تا نتیجه انجام می‌شود و بعد از خروج هر دو طرف به منو برمی‌گردند.
6. ۵ دقیقه بازی مداوم بدون کرش و بدون افت شدید فریم؛ FPS به‌طور محسوس پایدار حول هدف ۶۰ باقی می‌ماند.
7. در `adb logcat` هیچ `NullReferenceException` / `MissingReferenceException` مربوط به کد بازی تکرار نمی‌شود.

اگر هر کدام برقرار نبود، تست **پاس نشده** و باید به‌عنوان باگ ثبت شود (بخش ۵).

## ۵. ثبت باگ

هر باگ را با این قالب ثبت کنید:

```
عنوان: (یک خط، کوتاه و گویا)
محیط: دستگاه + نسخهٔ اندروید + نسخهٔ APK/کامیت (مثلاً 073a9db) + تک‌دستگاهی/دو‌دستگاهی
شدت: Blocker / High / Medium / Low
توضیح: چه اتفاقی افتاد و چرا مشکل است
مراحل بازتولید:
  1. ...
  2. ...
  3. ...
نتیجهٔ واقعی: ...
نتیجهٔ مورد انتظار: ...
بازتولیدپذیری: همیشه / گاهی (چند از چند بار) / یک‌بار
شواهد: اسکرین‌شات/ویدیو + خروجی adb logcat (فایل پیوست)
```

- اسکرین‌شات را با کلیدهای دستگاه بگیرید (`Power + Volume Down`) و همراه با **بازهٔ زمانی** لاگ در گزارش بگذارید.
- اگر باگ شبکه‌ای است، لاگ **هر دو دستگاه** را جمع کنید و ترتیب رخدادها را مشخص کنید.

## وضعیت تأیید فعلی

- در Play Mode و روی کامپیوتر: ۲۵/۲۵ تست رگرسیون پاس، کامپایل تمیز.
- روی **دستگاه فیزیکی: هنوز اجرا نشده** — این سند برای همان مرحله است.
